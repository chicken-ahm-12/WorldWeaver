01 / GETTING STARTED

Keep the three WorldWeaver modules together, create a settings instance, build its cache, then hand it to the generator.

01

Place the modules

For a simple Argon project, keep the modules under src/ServerScriptService/WorldWeaver/. The Generator already expects Painting beside it.

src/
└── ServerScriptService/
    └── WorldWeaver/
        ├── Generator.luau
        ├── Painting.luau
        └── Settings.luau
02

Create the required events

Settings.luau waits for ReplicatedStorage.Events.gridLoaded and terrainRendered. Both are fired as BindableEvents by the generator.

ReplicatedStorage/
└── Events/
    ├── gridLoaded
    └── terrainRendered
03

Generate from a server script

Require the modules, create a settings object, change the values you want, build the cache, then call Generator.generateTerrain(settings).

local WorldWeaver = script.Parent.WorldWeaver
local Settings = require(WorldWeaver.Settings)
local Generator = require(WorldWeaver.Generator)

local settings = Settings.new()
settings.Seed = 42
settings.MapWidth = 500
settings.MapBreadth = 500
settings:BuildCache()

Generator.generateTerrain(settings)
Recommended workflowDevelop with a normal server script and Play Test first. Once a map is stable, keep its settings in a dedicated preset script so the same world can be reproduced later.

  "tree": {

03 / SETTINGS REFERENCE

These are the settings you will normally use to shape terrain, control rendering, tune blending, configure noise, define biomes, and manage generation performance.

04 / NOISE & INTERPOLATION

WorldWeaver builds terrain from five named noise signals, each with a frequency, amplitude, and interpolation curve that maps noise to height. The Name and Priority parameters manage these signals, higher priority values reduce a signal's influence. The contribution decay across successive layers is controlled by Settings.Persistance.

ContContinentalnessPriority 1 · amp 4 · freq 2

Low-frequency landmass structure.

ErosErosionPriority 2 · amp −VoxelSize · freq 16

Higher-frequency height reduction/detail.

HumHumidityPriority 3 · amp 1 · freq 32

Fine-scale signal used heavily for biome identity.

PeakPVPriority 4 · amp 250 · freq 4

Major elevation driver in the default terrain curve.

TempTemperaturePriority 5 · amp 20 · freq 8

Biome signal with a moderate terrain contribution.

Adding a noise

Settings.NoiseNames.Moist = {"Moisture", 6}

Settings.NoiseDetails[Settings.NoiseNames.Moist[1]] = {
    amp = 8,
    freq = 12,
}

Settings.InterpolationValues[Settings.NoiseNames.Moist[1]] = {
    [0] = -4,
    [0.5] = 0,
    [1] = 8,
}

Why the cache matters

BuildCache() sorts interpolation keys and prepares the ordered noise list used by the generator. Call it after editing noise/interpolation configuration and before generating.

Noise→Interpolation→Height→Biome
05 / BIOMES

Painting.SetBiome checks each configured biome against the current noise values, calculates a penalty for values outside each range, and chooses the biome with the lowest total penalty.

Plains

Continentalness 0–0.5, Temperature 0–0.3, Erosion 0–1, PV 0–0.5. Amplitude 1.7.

Grass

Mountains

Continentalness 0–0.5, Temperature 0.3–1, Erosion 0–1, PV 0.5–1. Amplitude 2.6.

Desert

Continentalness 0.5–1, Temperature 0.5–1, Erosion 0–0.5, PV 0–0.4. Amplitude 1.

Best practiceWhen adding a biome, update both Biomes and BiomeDetails. Keep the noise keys in BiomeDetails aligned with your NoiseNames table. The biome's amp, Color and Material are part of rendering and height shaping, not decoration alone.
06 / PERFORMANCE
01

Prototype small

Start around 300–500 studs per axis while tuning. Maps around 600×600 or 800×800 are already substantial.

02

Align divisions

Keep MapWidth and MapBreadth equal where practical, and make them multiples of the rendering division or smaller than it.

03

Use built-in Terrain for very large worlds

It is recommended to have useInBuiltTerrain = true for maps around 2000×2000 studs or more, with fastBlend = true as a strong companion.

04

Control concurrency

GridCAP controls grid work while RenderThreadCap controls rendering work. Increasing both can raise throughput but also increases pressure on the server.

05

Generate test worlds

Keep a test server script with saved presets. This makes iteration faster than repeatedly rebuilding a final map before the shape is stable.

07 / API SURFACE
Settings.new()

Creates an independent settings object using the Settings table as its metatable.

Settings:BuildCache()

Builds the ordered noise and interpolation caches required by generation.

Generator.generateTerrain(settings)

Runs the grid phase, waits for it to complete, renders divisions, clears the height grid and fires the completion event.

Painting.SetBiome(arr, settings)

Selects the best matching biome and returns the biome name plus its normalized inverse score.

Settings:GetInterpolatedAmpValue(value, name)

Linearly interpolates a configured noise curve.

Settings:ValueInRange(range, num)

Checks a value against a NumberRange and returns whether the range exists plus its distance penalty.

Cache after configurationCall BuildCache() after changing interpolation or noise configuration and before generating terrain.
